# Android Push + Local Notifications Plan

### Scope

- Platforms: Android only
- Types: Firebase Cloud Messaging (push) + flutter_local_notifications (local display)

### Dependencies (pubspec.yaml)

- Add: `firebase_core`, `firebase_messaging`, `flutter_local_notifications`

### Android setup

- Place `android/app/google-services.json` (from your Firebase project).
- Update `android/build.gradle`: add `classpath 'com.google.gms:google-services:4.4.2'` in buildscript.
- Update `android/app/build.gradle`:
- `apply plugin: 'com.google.gms.google-services'`
- Set `minSdkVersion >= 21` (already typical)
- Ensure `android/app/src/main/AndroidManifest.xml` has `POST_NOTIFICATIONS` (already present) and the default Firebase messaging service entries (auto-registered by the plugin). No extra services needed.
- Add a monochrome small icon (optional, recommended) at `android/app/src/main/res/drawable/ic_stat_notification.xml` and reference it in initialization. Fallback: `@mipmap/ic_launcher`.

### Dart initialization

- Create `lib/shared/services/push_notification_service.dart` with:
- `FirebaseMessaging.onBackgroundMessage(_firebaseMessagingBackgroundHandler);` top-level handler
- Setup for `FlutterLocalNotificationsPlugin` and Android notification channel (e.g., id `high_importance_channel`).
- Methods: `initialize()`, `requestPermissionAndroid13Plus()`, `showLocalNotification(...)`, `handleMessageRouting(RemoteMessage)`.
- In `lib/main.dart`:
- Initialize Firebase via `Firebase.initializeApp()` (after Supabase init).
- Initialize `PushNotificationService.initialize()` early.
- Request POST_NOTIFICATIONS permission on Android 13+ (your `PermissionManager` can call `permission_handler` or delegate to service).
- Register foreground listeners: `FirebaseMessaging.onMessage` → call `showLocalNotification` and update `NotificationStore`.
- Register tap listeners: `FirebaseMessaging.onMessageOpenedApp` and `getInitialMessage()` for terminated state → route via `handleMessageRouting`.

### Data flow and storage

- On login (e.g., in `AuthStateManager` or after auth success), get FCM token via `FirebaseMessaging.instance.getToken()` and upsert to Supabase (e.g., `profiles.fcm_token` or `user_devices` with device_id). Use existing `supabase` client.
- When a push arrives, also insert/update in-app list via `NotificationStore.add(...)` or via your `NotificationManager` to keep UI in sync.

### Navigation on tap

- Parse `RemoteMessage.data` for keys like `route`, `id`, `type`, `action_url` and navigate accordingly (e.g., to `notification_screen.dart` or specific detail pages). Provide a safe default.

### Minimal code touchpoints

- `lib/main.dart`: initialize Firebase + register listeners.
- `lib/shared/services/push_notification_service.dart`: new file encapsulating all notification plumbing.
- `lib/shared/managers/notification_store.dart` and/or `shared/managers/notification_manager.dart`: invoked to mirror push in in-app state.
- Optional: small addition to `AuthStateManager` or your login flow to upload FCM token.

### Testing

- Use Firebase Console to send a test notification with both notification and data payload.
- Verify: foreground shows local notification, background/terminated shows system tray, tap routes correctly, in-app list updates, token saved in Supabase.
